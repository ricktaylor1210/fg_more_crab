# 普通螃蟹类型设计（基于当前资源包贴图）

## 1. 设计目标

这份设计用于补完当前资源包里 普通螃蟹的不同颜色与类型定义，让它们既能利用现有贴图资源，又符合 Minecraft 原版的生态语感。

当前普通螃蟹在 spec 中的定位是：

- 前期生态与食物来源
- 主要分布在海滩、浅海岸
- 以低门槛、可读性强、容易形成小型生态事件为主

因此，普通螃蟹的不同类型不应该做成“技能怪”或“半 Boss”，而应当做成：

- 继承基础实体 crab_normal 的行为下不同的颜色/生态子类型
- 主要差异体现在 生成环境、性格倾向、掉落偏向、驯服偏好
- 战斗差异只做轻度区分，避免抢走矿物螃蟹与 Boss 的设计空间

## 3. 总体设计原则

### 3.1 继承一个实体，独立生物多种外观与生态标签

普通螃蟹建议最终收口为：

- 继承crab_normal
- variant：颜色/生态子类型
- temperament：性格（胆小 / 护群 / 暴躁）
- is_tamed：是否已驯服

最终有
fg_crab_sandy
fg_crab_red_tide
fg_crab_blue_tide
fg_crab_frost_shell
fg_crab_coral
fg_crab_dusk_shell
fg_crab_moss_shell
独立实体继承crab_normal的行为然后做出区分

也就是说：

- 颜色 ≠ 性格
- 颜色 ≠ 是否攻击
- 颜色只负责生态身份与轻度玩法偏向
- 当前资源包中的 fg_crab / fg_crab_help / fg_crab_aggressive 是作为原型期实体，后续应尽量并回同一实体架构


### 3.2 差异要让玩家“看环境就能猜”

Minecraft 的好设计通常满足：

- 玩家不看 UI 也能大致猜出这是什么
- 生物颜色与环境/资源/群系有直觉联系
- 不需要记忆复杂说明书

因此，普通螃蟹颜色建议绑定到群系与地表材质：

- 沙色/橙色 → 普通沙滩
- 红色 → 暖海岸、红沙、晚霞海滩气质
- 蓝色 → 海水、礁石、潮间带
- 冰蓝 → 冰海岸
- 粉色 → 珊瑚暖海
- 紫色 → 夜晚/礁夜/暮色
- 绿色 → 海草、藻类、红树林潮湿地带

## 4. 七种普通螃蟹的最终设计

### 4.1 沙壳蟹 sandy

贴图来源：fg_crab_orange  
定位：标准普通螃蟹，会进行卧沙行为。

#### 生态与生成

- 海滩、浅海岸、碎石海岸边缘
- 白天更常见
- 生成权重最高

#### 行为倾向

- 默认以逃跑为主
- 受到 1 次攻击时优先撤离
- 同群体连续受击后，有小概率转为护群反击

#### 掉落偏向

- 生蟹肉：标准
- 蟹壳碎片：标准

#### 设计作用

- 作为玩家第一次接触螃蟹的默认版本
- 视觉直观，不会误导玩家“这是稀有怪”

### 4.2 赤潮蟹 red_tide

贴图来源：fg_crab_red  
定位：普通螃蟹里的“脾气稍大”分支。

#### 生态与生成

- 暖海岸、红沙海岸、靠近夕照色调的海滩
- 生成权重中等

#### 行为倾向

- 受击后更容易触发反击
- 群体警戒传播距离略大
- 更适合绑定“暴躁”性格权重

#### 掉落偏向

- 生蟹肉：标准
- 蟹壳碎片：略高于标准
- 可作为“基础钳类材料”偏好来源

#### 设计作用

- 给普通螃蟹增加一点“别把海边所有小动物都当完全无害”的感觉
- 但仍然属于前期可处理生物，不应做成高压战斗怪

### 4.3 蓝潮蟹 blue_tide

贴图来源：fg_crab_blue  
定位：最贴近潮间带生活的普通型。

#### 生态与生成

- 浅水海岸、礁石边、碎石滩
- 水边生成权重更高
- 可比其他普通螃蟹更愿意靠近浅水活动

#### 行为倾向

- 遇敌时更倾向沿水边横移
- 可给予略高的涉水移动效率
- 在水边更不容易卡行为

#### 掉落偏向

- 生蟹肉：标准
- 蟹壳碎片：略低
- 可额外承担“更容易被捕蟹笼捕到”的普通型权重

#### 设计作用

- 强化“海岸生态”的空间感
- 让玩家感受到不是所有普通螃蟹都只是站在沙子上乱走

### 4.4 霜壳蟹 frost_shell

贴图来源：fg_crab_ice  
定位：冰雪海岸的区域替换型普通螃蟹。

#### 生态与生成

- 雪地海滩、冰洋海岸、冰山边缘
- 寒冷群系限定
- 生成权重较低

#### 行为倾向

- 移动略慢
- 受到攻击后更倾向硬吃一下再撤离
- 可以给到轻度击退抗性或轻度护甲倾向

#### 掉落偏向

- 蟹壳碎片：高于其他普通型
- 生蟹肉：标准略低

#### 设计作用

- 作为冰雪海岸的视觉替换，不需要复杂技能
- 同时为基础蟹壳装备提供一个更明确的刷取方向

### 4.5 珊瑚蟹 coral

贴图来源：fg_crab_pink  
定位：暖海稀有观赏型 + 食材偏好型。

#### 生态与生成

- 暖海、珊瑚区域、热带海岸
- 稀有生成
- 更适合与海草、珊瑚扇、暖色海水环境同时出现

#### 行为倾向

- 偏胆小
- 视野内有玩家时更早撤离
- 不建议强化攻击倾向

#### 掉落偏向

- 生蟹肉：略高
- 可作为料理型螃蟹的优选来源
- 蟹壳碎片：标准偏低

#### 设计作用

- 给“抓蟹/做料理”链路一个更高价值但非战斗向的目标
- 用稀有暖海生态奖励探索，而不是靠数值碾压玩家

### 4.6 暮潮蟹 dusk_shell

贴图来源：fg_crab_purple  
定位：夜晚与礁岸环境中的稀有普通型。

#### 生态与生成

- 石滩、夜间海岸、阴影更多的海边区域
- 夜间权重提高
- 白天也可见，但概率显著降低

#### 行为倾向

- 更容易在夜间主动靠近腐肉/掉落物一类诱饵点
- 被发现后逃跑速度较高
- 可作为“难抓但不是强敌”的设计点

#### 掉落偏向

- 蟹壳碎片：标准
- 稀有掉落可以偏向壳粉 / 装饰类素材
- 不建议放强力战斗掉落，避免抢戏

#### 设计作用

- 补足普通螃蟹里的“时间条件差异”
- 让夜间海边探索有一点点新鲜感，但不转成恐怖玩法

### 4.7 潮苔蟹 moss_shell

贴图来源：fg_crab_experience  
定位：海草区/红树林边缘的功能型普通螃蟹。

#### 生态与生成

- 海草密集区、沼泽入海口、红树林边缘、潮湿海岸
- 偏少见，但不做极稀有

#### 行为倾向

- 偏温顺
- 更容易进入“可驯服候选”权重
- 对非料理类诱饵的靠近欲望更强

#### 掉落偏向

- 生蟹肉：标准
- 蟹壳碎片：标准
- 驯服成功率可给予轻度加成（如果你希望不同颜色真的有功能差异）

#### 设计作用

- 很适合承担“普通螃蟹 → 驯服螃蟹”的过渡角色
- 文件名里虽然叫 experience，但在玩法上更适合作为“生态友好型”而不是“经验蟹”

## 5. 最终推荐的生成方案

为了符合原版感，普通螃蟹不要做成平均分布，而是做成“默认 + 群系替换 + 稀有点缀”。

### 5.1 白天海岸默认池

- 沙壳蟹：高
- 蓝潮蟹：中
- 赤潮蟹：中低

### 5.2 冰雪海岸替换池

- 霜壳蟹：高
- 蓝潮蟹：低

### 5.3 暖海/珊瑚替换池

- 珊瑚蟹：中
- 沙壳蟹：中
- 赤潮蟹：低

### 5.4 潮湿/红树林替换池

- 潮苔蟹：中
- 蓝潮蟹：中低

### 5.5 夜间附加池

- 暮潮蟹：低到中低

## 6. 推荐的玩法区分边界

普通螃蟹的区分建议只做到下面这个强度，不要越界：

### 应该有的区别

- 群系差异
- 日夜差异
- 性格权重差异
- 掉落偏向差异
- 驯服难度差异

### 不建议现在就上的区别

- 独立技能树
- 主动释放远程技能
- 强控制效果
- 明显超出前期怪物的战斗强度
- 和矿物螃蟹/海盗螃蟹重叠的功能机制

## 7. 技术落地建议

### 7.1 数据结构建议

```text
entity: crab_normal
- is_tamed: bool
- has_backpack: bool
- fg:attack_mode: attack_left/attack_right/attack
- fg:attack_personality: calm/aggressive
```

### 7.2 贴图映射建议

```text
sandy       -> fg_crab_orange
red_tide    -> fg_crab_red
blue_tide   -> fg_crab_blue
frost_shell -> fg_crab_ice
coral       -> fg_crab_pink
dusk_shell  -> fg_crab_purple
moss_shell  -> fg_crab_experience
```

### 7.3 掉落表建议

- 基础掉落表：统一使用普通螃蟹主表
- 子类型差异：通过附加权重控制
- 不建议为 7 个普通型拆 7 张完全独立 loot table，维护成本太高

### 7.4 驯服系统建议

如果你准备让不同普通蟹真的影响驯服体验，建议只保留轻度差异。

注意：蟹肉棒、蟹肉寿司、蟹黄汤等自定义 food 不作为驯服道具。

- 潮苔蟹：更容易被食物吸引
- 珊瑚蟹：更适合作为高品质料理来源
- 赤潮蟹：驯服前更容易反击
- 其余类型维持中性

---

## 8. 最终结论

普通螃蟹的颜色设计，应该是分成不同生态子类型：

- 继承一个基础实体
- 七种生态子类型
- 轻度玩法差异
- 明显的环境识别度

这样既能吃满现有资源包的贴图价值，又不会把 V1.0 的基础生态复杂化，更符合 Minecraft 原版“颜色服务于生态与读图，而不是服务于说明书”的做法。
