## 1. 驯服系统

### 1.1 适用对象

- 普通螃蟹（后转化为驯服螃蟹 / 负重螃蟹）
- 未来可扩展到其他蟹种（如沙滩蟹、珊瑚蟹等）

### 1.2 驯服流程

- 玩家手持对应诱饵右键未驯服螃蟹：
  - 消耗 1 个诱饵
  - 按螃蟹变体和诱饵类型判定成功率
  - 蟹肉棒、蟹肉寿司、蟹黄汤等自定义 food 不作为驯服道具
  - 成功： 
    - 绑定主人 UUID
    - 播放爱心粒子与音效
  - 失败： 
    - 螃蟹对玩家进行一次攻击（轻微伤害）
- 已驯服且是主人：
  - 普通右键：跟随 / 待命 切换
  - Shift+手持「蟹壳背包」右键：给驯服蟹装备背包
  - Shift+手持剪刀右键已装备背包的驯服蟹：卸下背包并掉落背包物品

当前实现说明：

- 7 个正式普通生态螃蟹已接入跟随 / 待命切换。
- 背包打开、装备、卸下、跟随 / 待命交互都补了 `is_owner` 过滤。
- 待命通过移除 `follow_owner` 并临时把移动速度降为 0 表达，适合 MVP 验收。
- 已驯服普通蟹如果没有自定义名，脚本会补对应变体默认名，用于避免原生背包 UI 标题显示“未知”；玩家已用命名牌设置的名字不会被覆盖。
- 蟹壳背包已能被制作、装备到驯服蟹、卸下并掉落回收。
- 已装备背包时会添加 27 格原生 `minecraft:inventory` 容器，使用 `container_type: "container"` 与 `restrict_to_owner: true`；基础打开、放置物品和标题显示已实机可用，区块卸载、死亡和维度切换后的长线保存仍需继续回归。
- 卸下背包改由服务端脚本兜底：只有主人、潜行、手持剪刀且背包 27 格容器为空时才真正触发卸下；非主人、容器非空或无法读取容器时都会阻止卸下并给烟雾提示。

## 2. 负重螃蟹背包系统

### 2.1 数据结构

- 蟹实体中新增字段： 
  - `has_backpack: boolean`
  - `follow_state: follow / stay`
  - `backpack_item: ItemStack`
  - `crab_inventory: ItemStackHandler`（当前 Agent 式 `container` 为 27 格）

当前 JSON MVP 已落地 `fg:has_backpack`、`fg:follow_state` 和 27 格原生 `minecraft:inventory`。`fg:has_backpack` 已开启客户端同步，用于控制普通蟹背包模型显示。

### 2.2 装备 / 卸下流程

- 装备：
  - 条件：螃蟹已驯服，手持「蟹壳背包」，Shift+右键
  - 行为： 
    - `has_backpack = true`
    - 玩家物品栏减 1 个背包
- 卸下：
  - 条件：螃蟹已装备背包，主人 Shift+手持剪刀右键，且 27 格容器全空
  - 行为： 
    - 先检查 27 格原生容器是否为空
    - 掉落 1 个「蟹壳背包」到世界
    - `has_backpack = false`
    - 移除背包容器组件
    - 消耗剪刀耐久
- 保护：
  - 容器非空时不允许卸下，避免背包内物品被移除组件吞掉。
  - 脚本无法读取容器时按非空处理，优先保护库存。

当前卸下回收先按掉落物处理，不尝试直接塞回玩家背包。剪刀卸下用于保护库存交互：正常 Shift+右键留给原生容器打开，Shift+手持剪刀才进入卸下流程；如果容器非空，会冒烟并阻止卸下。

### 2.3 背包界面

- 当前优先使用原生容器，不先做自定义 UI。
- 第一方案：`container_type: "container"` + `restrict_to_owner: true`。
- 原生宠物背包 UI 标题由引擎绑定，语言 key 无效时会显示“未知”；脚本会在普通蟹驯服后尽早用对应变体默认名兜底，玩家已有自定义名时不覆盖。当前已实机确认标题可正常显示。
- 本轮 TASK-01~15 继续保留该方案，不自动切换到 `horse` + `minecraft:is_chested`；后续只继续观察保存、死亡、维度切换和多人边界。

## 3. 捕蟹笼系统

### 3.1 当前 MVP 形态

当前捕蟹笼先按可放置实体落地，不是方块 + BlockEntity。
捕蟹笼实体只通过捕蟹笼物品放置进入生存玩法，实体本身不再保留自然生成 / 生成蛋入口。

已接入 5 个品质：

- 普通捕蟹笼
- 铜捕蟹笼
- 铁捕蟹笼
- 金捕蟹笼
- 钻石捕蟹笼

品质主要影响：

- 等待时间
- 捕获成功率
- 被螃蟹破坏概率
- 捕获结果池权重

### 3.2 诱饵与交互

捕蟹笼使用“能驯服螃蟹的食物”作为诱饵：

- 鳕鱼
- 鲑鱼
- 热带鱼
- 腐肉
- 海带
- 干海带

玩家右键空笼时放置诱饵；已放诱饵后不再显示“可喂养”，只允许用其他有效诱饵替换。诱饵会持续播放低频粒子提示，收获后会清除上一次诱饵。

### 3.3 捕获与收获

捕蟹笼等待完成后进入可收获状态：

- 每隔数秒晃动一次，提示玩家可以收获。
- 在水中可收获时才浮起，并播放 holding 动画。
- 右键收获时发放物品或生成普通生态螃蟹。
- 螃蟹有低概率破坏捕蟹笼，品质越高越不容易被破坏。

捕蟹笼也能放在陆地，但陆地捕获概率降低为水中概率的 1/3。

### 3.4 当前平衡参数

| 品质 | 等待时间档位（秒） | 破坏概率 |
|---|---:|---:|
| 普通 | 60 / 90 / 120 | 8% |
| 铜 | 50 / 75 / 100 | 6% |
| 铁 | 45 / 65 / 90 | 4% |
| 金 | 40 / 60 / 80 | 3% |
| 钻石 | 30 / 45 / 60 | 2% |

### 3.5 可扩展方向

- 后续如果需要容器 UI，再升级为方块 + BlockEntity。
- 后续可按诱饵种类细分不同普通螃蟹权重。
- 矿物螃蟹、海盗螃蟹、Boss 幼体暂不放进当前捕蟹笼 MVP，避免破坏生态稀有度。

## 4. Boss 框架与阶段系统

### 4.1 当前实现

- 已接入 5 个 Boss 行为实体：熔岩、寒霜、毒沼、潮汐、回音守卫。
- 实体 JSON 使用 `minecraft:boss` 显示血条。
- 服务端脚本按生命比例触发 `fg:boss_phase_2` / `fg:boss_phase_3`。
- 服务端脚本按 Boss 类型释放主题控制 / 伤害技能，并在 P2 / P3 追加独立场地机制：熔岩火池 / 爆裂地面、寒霜冰面 / 冰刺 / 反制窗口、毒沼毒池回血 / 毒雾区、潮汐水流牵引 / 水位压迫、回音声波领域 / 黑暗与震动主题。
- Boss 不再通过自然 spawn rule 刷出，生存入口限定为脚本巢穴 / 神庙结构。
- 服务端脚本会按环境低概率放置 5 个展示级 `.mcstructure` 资源并刷出对应 Boss、补给宝箱和非核心奖励；每个巢穴 bucket 的结构和宝箱只生成一次，Boss 每 3 个 Minecraft 天重刷一次且战斗中不重刷；熔岩 Boss 巢穴维度 ID 当前按 `0` 处理。
- Boss 核心由 Boss 实体直掉，并已接入 5 套 Boss 护甲和 5 把 Boss 武器的配方；装备效果由脚本按手持武器、右键主动技能、完整套装和受击事件触发。

### 4.2 通用阶段划分

- 阶段 1：100% ~ 66% HP
- 阶段 2：66% ~ 33% HP
- 阶段 3：33% ~ 0% HP

各 Boss 各阶段行为详见：`docs/06_worldgen_and_bosses.md#各-boss-阶段设计`
