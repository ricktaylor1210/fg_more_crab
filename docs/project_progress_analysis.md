# 项目当前进度分析

分析日期：2026-06-15

## 1. 分析口径

本报告基于 `docs/`、行为包、资源包和当前可见脚本文件做静态判断。

需要注意：

- “完成度”按玩家可实际体验到的玩法闭环估算，不按素材数量估算。
- 除已由用户回归确认的负重背包基础功能外，本报告不判断其他运行时表现是否完全正确。
- 当前工作区存在大量未提交实现文件，本报告只同步文档口径，不回退实现。

## 3. 已经落地的内容

### 3.1 普通生态螃蟹

当前正式普通生态变体为 7 个独立实体：

- `fg:crab_sandy`
- `fg:crab_red_tide`
- `fg:crab_blue_tide`
- `fg:crab_frost_shell`
- `fg:crab_coral`
- `fg:crab_dusk_shell`
- `fg:crab_moss_shell`

这些变体已经接入行为包实体、资源包客户端实体、生成规则、刷怪蛋图集、语言条目和掉落表。

`fg:crab`、`fg:crab_help`、`fg:crab_aggressive` 仍可作为原型 / 兼容 / 调试实体理解，不再代表正式普通生态的全部范围。

### 3.2 捕蟹笼 MVP

捕蟹笼当前按实体版 MVP 落地，不是 BlockEntity 方案。

已接入内容：

- 普通、铜、铁、金、钻石 5 个品质。
- 鳕鱼、鲑鱼、热带鱼、腐肉、海带、干海带作为诱饵。
- 放置诱饵、替换诱饵、低频诱饵粒子、可收获晃动。
- 可收获时在水中浮起并播放 holding 动画。
- 陆地捕获概率降低为水中的 1/3。
- 收获后清除上一次诱饵。
- 螃蟹低概率破坏笼子，品质越高越稳定。

### 3.3 矿物螃蟹

矿物蟹策划口径已经从“一个实体 + OreType”改为 9 个独立实体：

- `fg:mineral_crab_coal`
- `fg:mineral_crab_copper`
- `fg:mineral_crab_iron`
- `fg:mineral_crab_gold`
- `fg:mineral_crab_redstone`
- `fg:mineral_crab_lapis_lazuli`
- `fg:mineral_crab_emerald`
- `fg:mineral_crab_diamond`
- `fg:mineral_crab_quartz`

当前实现方向：

- 每种矿物蟹有独立实体、资源入口、生成规则和掉落表。
- 服务端脚本扫描匹配矿石，寻找可站立接近点，靠近后消耗矿石。
- 吃矿后按类型触发差异化 Buff。
- 生成规则已按矿物类型绑定环境，铜矿蟹偏滴水石洞，金矿蟹偏恶地深层，绿宝石偏山地，石英偏下界。

### 3.4 海盗螃蟹

当前海盗蟹按 3 个职业实体落地：

- `fg:pirate_crab_sailor`
- `fg:pirate_crab_artillery`
- `fg:pirate_crab_captain`

已接入方向：

- 主动敌对和职业差异。
- 服务端脚本执行偷窃、携物逃跑、逃跑状态回落、击杀返还。
- 受伤后附近海盗蟹集结。
- 水边、沙砾、木质残骸、箱子、木桶等位置作为补刷锚点。
- 海岸小型藏身处脚本生成作为结构联动 MVP。

当前掉落口径：

- 击杀掉落保留职业差异化处理。
- 藏宝图加入少量直掉，但主要来源仍是小型藏身处和 Boss 结构宝箱。

## 4. 新增落地内容与仍需验收的边界

### 4.1 蟹肉 / 蟹壳碎片用途

基础材料已有掉落入口，并已扩展用途：

- 蟹肉棒、烤蟹肉、清蒸螃蟹基础配方。
- 清蒸螃蟹短时再生效果。
- 香辣蟹钳、蟹肉寿司、蟹黄汤、椰香蟹汤、蟹肉炒饭、蟹肉三明治、蟹肉味噌汤等功能料理。
- 蟹壳背包、蟹壳盾牌和蟹壳头盔 / 胸甲 / 护腿 / 靴子。

仍需游戏内验收：

- 料理效果是否都被当前引擎识别。
- 蟹壳护甲耐久、装备栏和防御值是否符合网易物品组件预期。
- 蟹壳盾牌脚本减伤、冷却和耐久消耗是否符合游戏内事件参数。

### 4.2 负重背包

资源侧背包骨骼已经挂到普通蟹模型，并由 `fg:has_backpack` 客户端同步控制显示。

当前实现：

- 已装备背包的普通驯服蟹添加 27 格 `minecraft:inventory`。
- 容器第一方案使用 `container_type: "container"` + `restrict_to_owner: true`。
- 装备、卸下、跟随 / 待命交互补 `is_owner` 过滤。
- 卸下改为主人 Shift+手持剪刀右键，避免和打开原生容器交互冲突。
- 卸下前脚本检查容器 27 格库存，非空或读取失败时阻止卸下，避免移除容器导致物品丢失。

实机结论：普通生物 Agent 式 `container` 容器已能打开 27 格、放置物品并显示有效标题；装备、空包剪刀卸下和非空阻止卸下流程可用。仍需继续回归区块卸载、死亡、维度切换后的库存保存和多人非主人边界。本轮继续保留该方案，不自动回退到 `horse` + `minecraft:is_chested`。

### 4.3 Boss、巢穴与终局内容

四大元素 Boss、循声蟹守卫已接入 TASK-01~15 主线静态闭环：

- 5 个 Boss 行为实体、客户端实体、本地化和掉落表；发布包关闭生成蛋入口，保留 `/summon` 调试入口。
- Boss 血条、基础近战、P2/P3 阶段切换。
- 服务端脚本按 Boss 类型释放主题技能，并在 P2 / P3 追加独立场地机制：熔岩火池 / 爆裂地面、寒霜冰面 / 冰刺 / 反制窗口、毒沼毒池回血 / 毒雾区、潮汐水流牵引 / 水位压迫、回音声波领域 / 黑暗与震动主题。
- 5 个 Boss 的自然生成规则已禁用，生存入口限定为脚本巢穴 / 神庙结构。
- 服务端脚本按环境低概率放置 5 类展示级 `.mcstructure` 巢穴 / 神庙资源，再刷出对应 Boss、补给宝箱和非核心奖励；结构和宝箱每个 bucket 只生成一次，之后 Boss 每 3 个 Minecraft 天重刷一次，战斗中不重刷；熔岩 Boss 巢穴维度 ID 当前按 `0` 处理。
- Boss 核心可拆解为蟹壳碎片，也可制作对应 Boss 套装和武器。
- 5 套 Boss 护甲、5 把 Boss 武器、基础配方、本地化、脚本命中特效、套装效果、右键主动技能、统一冷却、耐久消耗、粒子和原版音效命令已接入。

仍需验收：结构放置、临时方块恢复、宝箱 loot table、主动技能命令音效、游戏内数值和平衡。结构谜题、终局事件、蟹卵养殖、潮汐入侵和元素盾牌属于后续扩展。

## 6. 当前主要风险

### 6.1 文档和实现容易再次漂移

本轮已经把主要文档同步到当前实现，但配置指南仍以原型三蟹为讲解样本。后续新增实体时，需要明确样本和正式范围的区别。

### 6.2 实体数量增长带来维护成本

普通、矿物、海盗和捕蟹笼都采用多实体方式落地。优点是资源、生成和掉落独立；风险是语言、图集、掉落、生成和脚本映射容易漏一处。

### 6.3 脚本行为需要游戏内压力验证

矿物蟹吃矿、海盗蟹偷窃和捕蟹笼 tick 都依赖脚本状态。静态检查无法证明性能、边界和多人同步完全正确。

### 6.4 新接入原生容器、自定义盾牌和结构放置需要实测

背包采用 Agent 式 `container` 容器作为第一方案，基础打开、标题和卸下保护已实机可用，仍需继续观察区块卸载、死亡、维度切换和多人边界。盾牌采用自定义盾牌入口并保留 `DamageEvent` 兜底，Boss 巢穴采用生成器产出的 `.mcstructure` 和 `PlaceStructure` 放置；这两条仍需要在网易客户端里实测确认。若结构格式不被识别，应回退为脚本逐方块生成同款结构。

## 7. 建议下一步

1. 对普通生态螃蟹、捕蟹笼、矿物蟹、海盗蟹做游戏内验收，重点看生成、交互、脚本状态回落和掉落。
2. 修正验收中发现的概率、生成密度和性能问题。
3. 游戏内验收蟹肉 / 蟹壳碎片完整用途，并继续回归背包保存 / 死亡 / 维度切换、多人主人限制和跟随 / 待命切换。
4. 游戏内验收蟹壳护甲、蟹壳盾牌副手 / 抵挡 / 冷却 / 耐久。
5. 游戏内验收 5 个 Boss 的结构放置、Boss 生成、血条、阶段、P2/P3 场地机制、临时方块恢复、宝箱、掉落、核心拆解、Boss 装备配方和主动技能。

## 8. 阶段性结论

当前项目最强的部分：

- 普通生态螃蟹和共模资源链路已经成型。
- 捕蟹笼、矿物蟹、海盗蟹都已经有可测试 MVP。
- 服务端脚本已经承担复杂行为，突破了纯 JSON AI 的限制。

当前项目最缺的部分：

- 背包长线保存边界、自定义盾牌、结构放置、Boss 技能、宝箱 loot table 和 Boss 装备效果的游戏内兼容性确认。
- 结构谜题、终局事件、蟹卵养殖、潮汐入侵和元素盾牌等后续扩展。
- 游戏内长时间稳定性验证。
