# 项目当前进度分析

分析日期：2026-06-06

## 1. 分析口径

本报告基于 `docs/` 下的设计文档、开发路线图、行为包配置指南、资源包配置指南，并结合当前仓库中可见的行为包与资源包文件结构做静态判断。

需要注意：

- 这里的“完成度”按玩家可实际体验到的玩法闭环估算，不按贴图、模型、动画资源数量估算。
- 本次未进入游戏实测，因此不判断运行时表现是否完全正确。
- 当前工作区有若干行为包文件处于未提交修改状态，本报告只做读取分析，不修改这些实现文件。

## 2. 总体结论

当前项目已经从“三只基础原型螃蟹”推进到“七种普通生态变体已接入行为包与资源包”的阶段。

按路线图判断：

| 版本/范围 | 当前判断 | 说明 |
|---|---:|---|
| V1.0 基础生态与系统 | 约 35% ~ 45% | 普通螃蟹生态变体已有明显进展，但矿物蟹、海盗蟹、驯服、负重、捕蟹笼、料理、基础装备仍未形成完整闭环。 |
| V1.1 Boss 与套装 | 约 5% ~ 10% | 资源侧有大量预铺，未见完整 Boss 行为、阶段、巢穴、掉落装备链路。 |
| V1.2 终局内容 | 约 0% ~ 5% | 终局 Boss 与装备有资源痕迹，但玩法逻辑基本未落地。 |
| 总路线图 | 约 20% ~ 30% | 设计与资源储备较强，真正可玩系统仍集中在普通螃蟹生态入口。 |

一句话概括：

> 项目已经完成了普通螃蟹生态的第一轮扩展，但 V1.0 还没有完成“打螃蟹/捕螃蟹 -> 获得材料 -> 做食物或装备 -> 驯服/负重/扩展资源获取”的核心闭环。

## 3. 已经落地的内容

### 3.1 普通螃蟹实体与生态变体

当前行为包中可见 10 个螃蟹实体文件：

- 3 个原型实体：`fg_crab`、`fg_crab_help`、`fg_crab_aggressive`
- 7 个普通生态变体：`fg_crab_sandy`、`fg_crab_red_tide`、`fg_crab_blue_tide`、`fg_crab_frost_shell`、`fg_crab_coral`、`fg_crab_dusk_shell`、`fg_crab_moss_shell`

其中 7 个普通生态变体已经具备：

- 行为包实体定义
- 资源包客户端实体入口
- 生成规则
- 贴图映射
- 刷怪蛋图集键
- 中英文语言条目
- 普通/肉偏向/壳偏向掉落表引用

这说明 `docs/02_crab_normal_variant_design.md` 中的七种普通螃蟹设计，已经不只是文档规划，而是进入了实际接线阶段。

### 3.2 行为状态机已经形成基础模板

从 `docs/生物行为配置指南.md` 和当前实体文件结构看，普通螃蟹已经具备一套可复用行为模式：

- 用 `properties` 表示攻击模式、攻击人格、避让状态等轻量状态
- 用 `component_groups` 承载愤怒、避让、左击、右击、双击等可切换能力
- 用 `events` 负责状态切换
- 用行为包动画与动画控制器驱动攻击循环和短时状态生命周期

这部分是当前项目最有价值的工程基础。后续矿物蟹、海盗蟹、Boss 小怪如果继续复用这套模式，可以减少重复配置。

### 3.3 资源包共模策略已经跑通

资源包侧普通螃蟹已经形成稳定策略：

- 共用 `geometry.crab`
- 共用基础动画、攻击动画、姿态控制器和通用渲染控制器
- 通过 `client_entity` 的 `textures.default` 和 `spawn_egg.texture` 区分变体

这与资源包配置指南中的设计方向一致，说明当前资源架构适合继续扩展同骨架螃蟹。

### 3.4 基础材料与掉落有雏形

当前行为包和资源包中已经有：

- `crab_claws`
- `crab_shell_powder`
- 普通螃蟹掉落表
- 肉偏向掉落表
- 壳偏向掉落表
- 一个蟹穴宝箱掉落表 `crab_burrow_basic.json`

这说明“击杀螃蟹获得基础材料”的入口已经存在，但这些材料的后续用途仍需要补齐。

## 4. 仅资源预铺或尚未闭环的内容

### 4.1 矿物螃蟹

文档目标：一个 `crab_mineral` 实体，通过 `ore_type` 表示煤、铜、铁、金、红石、青金、绿宝石、钻石、石英等类型，并具备吃矿强化和对应掉落。

当前状态：

- 资源包已有 9 张矿物螃蟹贴图。
- 当前未见矿物螃蟹行为实体、生成规则、`ore_type` 属性、吃矿逻辑、矿物掉落闭环。

判断：资源已准备，玩法逻辑未落地。

### 4.2 海盗螃蟹

文档目标：靠近玩家后偷取高价值物品，逃跑，被击杀后返还被偷物并掉落藏宝类奖励。

当前状态：

- 资源包已有海盗蟹模型、动画、贴图和物品图标。
- 当前未见海盗蟹行为实体、偷窃逻辑、逃跑 AI、海盗结构生成或专属掉落闭环。

判断：资源预铺较多，行为玩法未开始或未接入。

### 4.3 驯服与负重系统

### 4.4 捕蟹笼系统

### 4.5 食物、配方与基础装备

文档目标：蟹肉料理、蟹壳装备、盾牌、背包等基础物品构成 V1.0 经济与成长线。

## 6. 当前主要风险

### 6.1 文档与实现进度不同步

两份配置指南仍主要围绕“三只螃蟹”说明，而当前工程已经出现 7 个普通生态变体。

风险：

- 后续开发者按指南新增内容时，可能忽略当前 7 变体架构。
- 文档中的旧路径引用也需要后续统一，例如部分文档仍指向旧编号文件名。

### 6.2 原型实体与正式生态变体并存

当前同时存在：

- `fg_crab` / `fg_crab_help` / `fg_crab_aggressive`
- `fg_crab_sandy` 等 7 个正式生态变体

风险：

- 如果不明确哪些是保留原型、哪些是正式实体，后续生成规则、掉落、刷怪蛋、语言名称会越来越难维护。
- 当前 7 个普通变体有生成规则，3 个原型实体未在当前生成规则列表中看到对应规则，需要确认它们是否只保留为调试/兼容实体。

### 6.3 资源数量明显领先于玩法逻辑

资源包已经为矿物蟹、海盗蟹、Boss、装备、捕蟹笼、背包和料理准备了大量素材。

风险：

- 如果继续优先铺资源，项目会变成“素材很多但不可玩闭环不足”。
- 后续一旦行为架构变化，大量资源入口可能需要返工接线。

### 6.4 基础经济闭环不足

当前材料掉落已经有入口，但料理、配方、装备、驯服、捕蟹笼没有闭环。

风险：

- 玩家即使遇到并击杀螃蟹，也缺少后续目标。
- 普通螃蟹生态变体的价值会停留在“换皮 + 少量掉落差异”，不能支撑 V1.0 长时间体验。

### 6.5 个别引用需要复核

静态核对时发现 `fg_crab_aggressive.json` 当前引用的是 `loot_tables/entities/fg_crab_help.json`，而仓库中同时存在 `fg_crab_aggressive.json` 掉落表。

风险：

- 这可能是有意复用，也可能是漏改。
- 如果是漏改，暴躁螃蟹的掉落表现会与预期不一致。

## 7. 建议下一步

### 7.1 第一优先级：收口普通螃蟹体系

目标：

- 明确 3 个原型实体是否继续保留。
- 明确 7 个普通生态变体是否作为正式 V1.0 普通螃蟹体系。
- 更新行为包/资源包配置指南，让文档从“三只原型”同步到“七变体 + 原型兼容”的现状。
- 复核每个普通变体的掉落表、生成规则、语言、刷怪蛋图集、资源入口是否一致。

原因：

- 这是后续矿物蟹、海盗蟹、驯服、捕蟹笼复用基础螃蟹架构的前提。

### 7.2 第二优先级：补齐基础材料用途

目标：

- 至少实现 2 ~ 3 个基础料理或基础物品配方。
- 让 `crab_claws` 和 `crab_shell_powder` 从“掉落物”变成“有用途的资源”。

原因：

- 这是最快形成 V1.0 小闭环的方式。
- 不需要马上实现复杂 AI 或 Boss，即可提升当前可玩性。

### 7.3 第三优先级：选择一个核心系统做 MVP

建议二选一：

- 如果想强化资源循环，先做捕蟹笼 MVP。
- 如果想强化模组辨识度，先做驯服 MVP。

当前更建议先做捕蟹笼 MVP：

- 捕蟹笼可以复用现有普通螃蟹变体。
- 系统边界比驯服 + 背包 UI 更小。
- 能更快把普通生态变体、掉落和材料用途串起来。

### 7.4 第四优先级：再推进矿物螃蟹

矿物螃蟹是很适合作为 V1.0 中后段内容的任务，但建议在普通体系和基础材料用途稳定后再做。

原因：

- 矿物蟹需要新属性、新生成、新掉落、新强化逻辑。
- 如果普通螃蟹的实体架构还没收口，矿物蟹会复制当前不稳定结构。

## 8. 阶段性结论

当前项目最强的部分：

- 普通螃蟹资源与行为模板已经成型。
- 七种普通生态变体已经进入实际接线。
- 资源包为后续内容准备充分。

当前项目最缺的部分：

- V1.0 玩法闭环。
- 材料用途、配方、捕蟹笼、驯服等系统接线。
- 文档与当前实现的同步。

推荐近期方向：

> 暂停继续铺 Boss 和终局资源，先把普通螃蟹体系、基础材料用途、捕蟹笼或驯服 MVP 打通，让 V1.0 从“能生成和战斗”推进到“能持续游玩”。
